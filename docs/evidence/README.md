# Evidence from the LinuxONE VM

Captured on **2026-10-17 at 21:18 to 21:19 UTC (2026-10-18, about 02:48 IST)** from the datathon VM (IBM LinuxONE, RHEL 9.8, s390x, 3 vCPUs) over SSH, by Giridharan's session. Times in the images are the VM's own clock. Images `04` and `10` were captured later, on **2026-10-18 at 13:52 to 13:53 UTC**, the same way (see their rows).

**How the images were made, read this first.** The capture tool was a command line, not a screen recorder, so these PNGs are **renders of the unedited command output**: the text was copied as the SSH session returned it and drawn into an image (header line, command, output, a footer that says so). Nothing in the output text was edited. Two display changes only: lines longer than 175 characters are wrapped, and in image 06 the `edges` list of the ring is replaced by a count and the member list is cut to six (the command line printed in the image says so). If the judges or the team want pixel screenshots of a live terminal, run the same commands and screenshot them; the commands are below.

No address, key or token appears in any image (only loopback addresses). The Jupyter token file was never read.

## Things that do not match, or were not done

1. **`04` (resolved on 2026-10-18).** The first version of this image showed `bash infra/setup_vm.sh --check --tests` stopping with `ModuleNotFoundError: No module named 'sklearn'` (`ml/stack.py` imported `sklearn` at the top, and the serving venv `~/nexusz-venv` deliberately has none). PR #40 made that import lazy. The new image is the same command on `main` at `54d668c`: `238 passed, 6 skipped`, exit code 0. The earlier runs (155 passed, 5 skipped in the serving venv with `test_stack.py` excluded; 77 passed, 1 skipped inside the container) are in the git history of this file and are no longer needed.
2. **`05`:** the API container was already running (started by Ramana about 15 minutes before the capture). It was not started, restarted or stopped by this session. `refreshes_completed` is 0 because no replay was running.
3. **`10` (captured on 2026-10-18).** The run needs the VM to be otherwise idle. When it was started another session was running a 45-second replay on the shared account, so the run waited until that replay had ended and the VM showed 99.8% idle and load 0.00; no replay ran during the measurement (checked before and after). The counts are close to, but not identical with, the run in `docs/ML_RESULTS.md` section 8 (dense ALL 4,219 now against 6,504 in the earlier run, Granite 36,112 against 36,368, trees 0 in both), so they vary from run to run: quote them as *zero for trees, thousands for the network, tens of thousands for Granite*, not as exact figures. `accelerator_counters.txt` now holds this run's output. `docs/ML_RESULTS.md` was not edited.
4. **Freshness wording:** the task file says "about 12 seconds on the idle VM". `docs/PLATFORM_RESULTS.md` has 12.27 to 12.61 s for the bare process (3b) and 9.63 to 9.91 s for the final container (3c). The video script says "about ten to twelve seconds", which both support.
5. `09` lists eleven capability names under "dropped capabilities"; the script starts the container with all capabilities dropped. The check that matters is the effective mask read from inside the container, `CapEff: 0000000000000000`, which shows no capability is granted.
